## 项目经历

### 项目一：企业知识库智能问答系统（RAG 混合检索）

**项目背景**：针对"企业内部文档分散、员工查询靠翻文档和问同事"的痛点，从零构建企业知识库问答系统：员工自然语言提问，系统检索相关片段，由大模型依据资料生成带引用来源的回答，可跳转原文核验。核心挑战：口语化提问与书面表述不一致、答案必须可溯源、库外问题需准确拒答。

**技术栈**：Python · FastAPI · text-embedding-v3（通义）· Chroma · BM25 · LangGraph · DeepSeek / Qwen · numpy

**个人职责**：
- 知识库构建与数据治理：梳理制度、FAQ、产品手册等原始文档，清洗格式噪声后按主题切分为知识块，保留元数据；设计增量更新流程保证知识库与文档同步。
- 混合检索方案设计：用 numpy 手写余弦相似度验证检索原理；针对"口语化提问 vs 书面文档"关键词不匹配导致纯向量漏命中的问题，实现向量 + BM25 双路召回、RRF 分数融合与重排。
- 可信回答机制：回答强制标注引用来源（文档名 + 原文链接），实现库外问题自动拒答的防幻觉机制。
- 服务化封装：基于 FastAPI 封装 /ask 接口，支持多轮追问与查询改写，输出可被前端或企业内部 IM（飞书、企微）集成的问答服务。

**项目成果**：交付可演示的中文知识库问答系统：自然语言提问秒级返回带引用的回答、可跳转原文，库外问题准确拒答；搭建真实提问场景的评测集与评估脚本，支持 hit@5、MRR 持续回归对比，代码与 README 开源至 GitHub。

### 项目二：基于 LangGraph 的智能客服 Agent（含人工审批）

**项目背景**：针对"大模型直接面对用户不可控、高危操作不敢全自动"的痛点，构建有状态、有工具、有人工审批兜底的客服 Agent：低危请求（查订单 / 查物流）全自动，高危请求（退款 / 改地址）自动挂起转人工审批，批准后才执行。

**技术栈**：Python · LangGraph · SQLite（checkpointer）· Function Calling · FastAPI · DeepSeek · React

**个人职责**：
- 状态机与记忆设计：基于 LangGraph StateGraph 设计客服 Agent 状态机，用 SQLite checkpointer 实现多轮对话记忆与跨会话恢复，重启后历史会话可还原、长会话不串台。
- 工具编排：设计订单 / 库存 / 物流查询等工具的 JSON Schema 与 ReAct 编排循环，让模型按需自主选工具、传参、取结果，调用过程可被日志回放。
- 人工审批机制：实现 human-in-the-loop——对退款、改地址等敏感操作在工具执行前通过 interrupt 挂起会话，提供人工审批入口，批准后恢复执行，形成"低危自动 / 高危人审"边界。
- 服务化封装：基于 FastAPI 封装 /chat 与 /approve 接口，配合 React 演示页可视化"挂起 → 审批 → 继续"三幕流程。

**项目成果**：跑通低危全自动与高危必经人工审批两条完整链路，演示页可视化"挂起 → 审批 → 继续"三幕；会话重启后可恢复、调用日志可回放。

### 项目三：多智能体协作系统（Supervisor 模式）+ MCP + Docker

**项目背景**：针对"复杂任务单 Agent 效果差、工具接入各自为政、交付部署困难"三个痛点，构建 Supervisor 主管-专家模式多智能体系统：主管拆解任务并路由给检索 / 写作 / 质检三个专家 Agent，质检不合格自动退回重写；工具通过 MCP 协议标准化接入；整体容器化一键交付。

**技术栈**：Python · LangGraph · MCP（langchain-mcp-adapters）· Docker / docker-compose · DeepSeek · Prometheus

**个人职责**：
- 架构设计：搭建 Supervisor 多 Agent 架构，主管节点动态路由，三个子 Agent 各自独立子图、职责单一；通过消息总线实现上下文在子图间流转，避免单 Agent 上下文污染。
- 质检循环：实现 Critic 质检 Agent 循环，输出结构化修改意见（维度化打分 + 修改建议），不合格自动退回写作 Agent 重写；配置最大轮次防死循环并设兜底降级策略。
- MCP 标准化接入：通过 langchain-mcp-adapters 接入自建 MCP Server，使 Agent 能力可插拔扩展——新增 / 更换工具无需改业务代码。
- 容器化交付：编写 Dockerfile 与 docker-compose.yml，密钥通过 .env 注入而非硬编码，一条命令启动整套服务，可复现、可移植。

**项目成果**：端到端自动完成"资料调研 → 报告撰写 → 质量把关 → 交付"复合任务，日志完整展示多 Agent 交接过程；架构可扩展：新增专家 Agent 或新工具均为"加节点 / 加 MCP Server"级别改动。
