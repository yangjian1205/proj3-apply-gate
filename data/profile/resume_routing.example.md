# 简历路由

> 回答一个问题：**我有几版简历，哪版投什么岗位族？**
> `tailor` 单元的改写起点由这里决定 —— 它不重写整份简历，而是从对应版本 + 经历库里挑最相关的卡片重组。

## 当前版本

| 版本 | 文件 | 投向岗位族 | 状态 |
|---|---|---|---|
| A 版（主版） | `data/profile/resume.md` | AI Agent 开发 / LLM 应用开发 | 已在用 |
| B 版 | 暂无 | 数据工程 / 后端工程 | 未建 |

## 路由规则

```
JD 里出现 LangGraph / Agent / RAG / Function Calling / MCP  →  A 版
JD 是纯后端 / 数据工程，不涉及 LLM                              →  建议新建 B 版，当前回退 A 版
JD 是算法 / 模型训练岗（要求微调、训练、论文）                    →  A 版不合适，走人工
```

## A 版的改写重点（tailor 拿到的提示）

- **顺序**：项目一 / 项目二 提到工作经历之前（转行者靠项目说话，不靠年限）
- **必留**：214 个知识块、50 题评测集、hit@5 / MRR、interrupt 人审、RRF 双路召回 —— 这些是量化证据
- **可压**：自我评价、基础信息里的非技术项
- **禁改**：任何数字、日期、公司名、学校名、证书状态（这是 `provenance` 会拦的地方）

## 为什么需要这份文件

三个项目共用一份简历投所有岗位 = 海投。但按岗位改简历又容易改出编造。
这份路由的作用是：**把「改哪一版、改哪几段」这件事先定死**，让 `tailor` 只做重排与重述，不做加法。
