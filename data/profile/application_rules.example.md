# 投递规则

> 这份文件决定你「省多少时间」。**「直接跳过」那一栏写得越狠，你省的时间越多。**
> 注意：这里写的是**你的主观偏好**，会作为软条件参与打分；
> `data/rules.json` 里写的是**客观事实冲突**，才会产生硬拦截。两者不要混。

## ① 优先投（最高优先级，见到先处理）

- AI Agent 开发 / LLM 应用开发 / AI 应用工程师，岗位职责里明确出现：LangGraph、Agent 编排、RAG、Function Calling、MCP
- 公司类型：AI 原生创业公司、有真实 LLM 落地场景的团队
- 岗位写明「接受有完整项目经验的转行者」「能力可放宽」「年限可谈」
- 技术栈与我的三个项目有重叠：Python / FastAPI / LangGraph / 向量检索

## ② 可以考虑

- 岗位方向对但技术栈部分不重合（比如要求 Java 但做 LLM 应用）
- 职级写「资深 / 专家」但职责描述偏工程落地（职级不影响硬判定，只影响打分）
- 要求年限比我的实际年限多 1—2 年（系统会提示，不会拦）
- 外包 / 驻场但岗位内容确实是我要做的方向

## ③ 直接跳过（见到不留恋）

**这一栏写的是你的偏好，不会产生硬拦截，只在打分时扣分。** 想让它变成硬拦截，得改成 `data/rules.json` 里的规则（需要客观可判定才行）。

- 单休 / 大小周 / 明确写「能接受高强度加班」
- 长期驻场、出差占比写明超过 30%
- 岗位实际是销售 / 售前 / 实施冒充研发
- 招聘信息里出现「培训费」「押金」「需先付费」等
- 岗位与 AI 完全无关，只是名字里带「智能」

## ④ 交给我自己判断（系统不许猜）

- 公司规模、行业前景、团队是否有真实技术积累
- JD 信息不全（没写城市、没写年限、没说是否远程）→ 系统会输出「待确认」而不是猜
- 薪资是否匹配
- 是否值得为这个岗位单独准备材料

## 硬门槛三档（系统的判定立场，写在这里备查）

系统的硬拦截只认下面四类**客观事实冲突**，一句模型调用都不花：

| 触发条件 | 例子 |
|---|---|
| 岗位明写不提供签证支持，而档案里需要签证支持 | 「本岗位不提供工作签证支持」 |
| 岗位明写必须 base 某城市且不接受远程，而该城市不在期望城市里 | 「base 北京，不支持远程办公」 |
| 岗位明写学历门槛高于我的学历 | 「硕士研究生及以上学历」 |
| 岗位要求必须持有某证书，而我没有 | 「须持有 PMP 证书」（写「优先」不算） |

另外两类是**阈值硬**：要求年限比我多 3 年及以上 → 自动拒；多 1—2 年 → 只提示。
还有三类**不参与硬判定**，只打分：职级高低、技能覆盖度、行业背景。

**立场一句话**：拦你的必须是客观事实冲突；凡是需要「判断」的一律不拦，只打分。
