# units/cost-report · 记账与出稿

## 我负责什么

两件事，都是纯代码：

**① 成本记账** —— 每次模型调用记 `node / model / input_tokens / output_tokens / cost_cny / peak / elapsed`，
汇总到 `data/audit.db` 的 `cost` 表，并进 `output/<jd_id>/` 的报告。

**② 出稿** —— 批准后写四个文件到 `output/<jd_id>/`：

| 文件 | 内容 | 给谁看 |
|---|---|---|
| `resume.md` | 定制简历 | 你复制到招聘平台 |
| `cover_letter.md` | 招呼语 / 求职信 | 你复制到聊天框 |
| `evidence.md` | 溯源报告：每个数字 / 年限 / 公司名的出处清单 | 你自己留着复核 |
| `verdict.md` | 判定报告：三分类结论 + 依据引文 | 你复核「为什么」

## 价格口径（写在这里，免得被问）

按 DeepSeek 官方价格表的**高峰 / 空闲两档**分别计费，不是取平均：
- 高峰时段：北京时间周一至周五 9:00—12:00、14:00—18:00
- 其余时间（含周末全天）为空闲时段，价格是高峰的一半

出处：https://api-docs.deepseek.com/zh-cn/quick_start/pricing （2026-10-06 读取）

**已知不精确一处**：官方定义里「不含中国法定节假日」这一条没有实现（需要节假日日历），
所以法定节假日会被误判成高峰 → 成本**略微高估**。宁可高估不可低估。

## 不归我管的

- 我不判断该不该出稿（那是 approval）
- 我不重算模型给的判定（那是 hard-gate / match-score）
- **写库失败要报错，不许静默** —— 记账不能丢

## 错误策略

| 情况 | 行为 |
|---|---|
| `cost` 表写入失败 | 抛异常，**不吞** —— 记账丢了等于成本指标是假的 |
| 输出目录已存在 | 覆盖（同一 jd_id 重跑是正常行为），但会在报告里标注重跑轮次 |
| 未知模型名 | 按 `deepseek-flash` 计价，并在报告里标 `unknown_model`，**不静默给 0** |
| 产物里出现黑名单词 | 交给 approval 的产物扫描处理，我这里只负责不写 |
